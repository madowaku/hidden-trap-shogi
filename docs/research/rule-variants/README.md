# 落とし穴将棋 第二次研究：王手ルーレット（2026-11-17）

第一次研究（PR #2）で、新 Hard 同士 1000 局のうち 963 局が「王手の受けを罠で潰されて王を取られる」決着になった。
この研究では Bot の勝率ではなく、**ゲームそのものの形**を調べた。

- **現行ルールは変更していない。** 変種ルールは `scripts/research/` の比較実験の中だけで動く。reducer・アプリの Bot・オンラインには入っておらず、`tests/static/rule-variants.mjs` で固定している。
- 採用するかどうかは、オーナーが試遊で判断してください。この文書の数字は Bot 同士の自動対戦と、小さな盤での厳密解析だけに基づく（人間の試遊はしていない）。

## 結論（先に）

1. **963/1000 はルール本来の性質。Bot の偏りではない。**
   - 評価関数も読みの打ち切りもない小さな盤の均衡プレイでも、決着局の 88〜92% が同じ形で終わる。
   - 罠がなければ、その盤は王手の千日手で引き分けになる。罠は「王手の応手を潰す」ことで、引き分けを勝ちに変える装置になっている。
   - 読みの深さ（1・2・3 手）や癖読みの有無を変えても、この割合は 96〜97% で変わらない。
   - この割合が下がるのは、王手をまともに受けられない弱い Bot（Easy・Normal）のときだけ。
2. **ただし「くじ引きで勝負が決まる」わけではない。** ルーレットで死ぬ側は、その時点ですでに大きく負けている（評価 -0.81。互角（|評価| < 0.3）からのルーレット死は 7%）。王手ルーレットの正体は「勝っている側の仕上げが、詰みより大幅に簡単」という性質。
3. **王手 1 回の死亡率は約 29%**（受けが 2 通りで 30%、5 通り以上でも 13%）。普通の将棋なら「受けが 1 つでもあれば安全」なところが、ここでは毎回の推理勝負になる。罠側が実際にそのマスへ置いた確率（27.9%）と観測された命中率（27.3%）はほぼ一致しており、受ける側の読み違いによる偏りはない。
4. 変種を比べると、ゲームの性格がはっきり分かれる（数字は §4）。

| | A 現行 | B 王は罠無効 | C 王手の救済（指し直し） | D 王手をかけた手番の罠は無効 |
| --- | --- | --- | --- | --- |
| 手数（中央値） | **26** | 88 | 47 | 116 |
| 決着が罠由来 | 97% | 60% | 75%（ほぼ全て罠詰み） | **0%** |
| 王手 1 回の死亡率 | 29% | 8% | 12% | 6% |
| 逆転勝ちの割合 | 40% | 59% | 53% | **63%** |
| 読み合いの発生率 | **30%** | 24% | 19% | 25% |
| ひとこと | 短く、罠が濃い。最後は王手の連打 | 王が安全になり長期戦。罠は王以外の駒に | ルーレットは消えるが「受け 1 つ＝罠詰み」が残る | 罠が中盤に集中し、終盤は本将棋の寄せ。「王手か罠か」の二択が増える |

試遊するなら **A と D の比較**が一番情報が多いと考える（性格が最も違い、どちらも決着がつく）。B は中間、C は A との差が小さい。

## 1. 優先度 1：相手の未公開の罠がログから漏れていた件（修正済み）

`GameView.log` に相手の `pitfallSet`（相手が置いた罠の位置）がそのまま入っていた。相手の最新ログの `pitfallSet` は「今まさに自分を狙っている罠」なので、オンライン対戦のクライアントに答えが届いていた。

**修正**（`src/game/view.ts` の `getPublicLog`）:

| ログの持ち主 | 対局中に見えるもの |
| --- | --- |
| 自分 | すべて（自分の罠は自分が知っている） |
| 相手 | 次の自分の手番で発動・公開された罠だけ。今有効な罠、Strict で不発だった罠は消える |
| 観戦者 | 両者とも「相手」と同じ扱い |
| 終局後 | 全員にすべて（罠履歴レビューのため） |

- 型は `PublicLogEntry`（`pitfallSet` が省略可能）に分けた。アプリ側は `src/app/page.tsx` の末尾のヘルパー 2 つ・`GameLog.tsx`・`reaction.ts` の型を合わせただけ。PR #1 とは衝突しない（`git merge-tree` で確認）。
- テスト（`tests/static/public-log-hidden-information.mjs`、10 件）:
  - 実戦の全局面 × 先手・後手・観戦者で、「相手の未公開の罠だけを書き換えた 2 つの状態から配られるビューが完全一致する」こと（Casual / Strict）。
  - オンラインのルームが実際に送る JSON に、未公開の罠が入らないこと。
  - 終局後は全公開されること。Hard の判断が変わらないこと。
  - 修正を外すと 10 件中 8 件が失敗することを確認済み（残り 2 件は終局後の全公開と、Hard の判断不変の確認で、漏れの有無に関係しない）。
- 現行ルールでの Hard の判断は、修正前と 793 局面すべてで完全一致した。

## 2. 比較したルール

| | ルール | ねらい |
| --- | --- | --- |
| A | 現行ルール | 基準 |
| B | 王の移動は罠にかからない（王以外の駒、合駒・打ち・駒取りの受けは罠にかかる） | ご依頼の案 |
| C | 王手されている時の応手が罠で失敗したら、罠を見てから指し直せる（指し直しの手は罠にかからない。罠のマスには指せない） | ご依頼の救済案 |
| D | 王手をかけた手番に置いた罠は無効になる（位置は公開しない）。王手された側には罠がない | 追加案。「王手をかけるか、罠を活かすか」の二択を作る |

C の別案（「王手中は罠が効かない」「王手された側は罠の位置を見られる」）は、罠を置く側の最善が「一番いい受けに置く」になるため、どちらも C と同じ価値になる。そのため C に代表させた。

## 3. 実験の方法

- **Bot**: 第一次研究の読み合いエンジンに `rules` オプションを足し、探索の各手番で変種ルールを適用するようにした。変種ルールを知らない Bot で比べると、ルールの差ではなく Bot の不慣れを測ってしまうため。アプリからは渡しておらず（既定 = 現行ルール）、現行ルールでの出力は変更前と完全一致する。
- **ルールの適用**: `scripts/research/variant-rules.mjs` が reducer の外側で変種ルールを再現する（reducer は無変更）。
- **対局**: 読み合いエンジン同士、Casual 各 400 局・Strict 各 200 局。先後は 1 局ごとに入れ替え、300 手で引き分け。seed は Casual 30000〜、Strict 40000〜。
- **厳密解析**: `scripts/research/exact-mini.mjs`。§5 を参照。

### 指標（勝率以外）

| 指標 | 定義 |
| --- | --- |
| 決着理由 | 負けた側の最後の手番で分類。**ルーレット** = 受けの着地点が 2 つ以上あり、受けを選んだのに罠で失敗。**罠詰み** = 受けの着地点が 1 つしかなく、そこに罠。**詰み** = 受けがない。**必至** = 負けを読み切った局面（評価 ≤ -0.95）で王を取られる形にした。**受け損ね** = 受けがあったのに受けなかった |
| 王手 1 回の死亡率 | 王手された手番のうち、次の相手の手で王を取られた割合 |
| 逆転勝ち | 勝者が 10 手目以降に一度でも評価 -0.3 以下まで押された対局の割合 |
| 形勢の入れ替わり | 評価の符号が ±0.15 を越えて入れ替わった回数 |
| 決着が見えた時点 | 勝者側の評価が最後まで 0.6 以上だった最初の手。対局の何割の地点か（大きいほど最後まで分からない） |
| 読み合いの発生率 | 有力な手（着手確率 10% 以上）が 2 つ以上あり、成功と失敗の差が 0.15 以上ある手番の割合 |
| 罠の圧力 | 「罠がなければ得られた最善の価値」と「読み合い込みの価値」の差の平均 |
| 戦略の多様性 | 着手・罠の選び方のエントロピー（bit）、序盤 8 手の重複のなさ、王を取った駒の種類のエントロピー |

形勢はエンジン自身の評価なので、変種ごとに物差しが少しずつ違う。数字の細かい差より傾向を見てください。

## 5. なぜ 963/1000 がこの決着になったのか（優先度 3）

### 仮説と検証

| # | 仮説 | 検証 | 結果 |
| --- | --- | --- | --- |
| H1 | ルール本来の性質。罠を置く側は罠と王手を同じ手番に決められるので、受け方が限られる王手は「推理勝負」になり、毎回一定の確率で死ぬ | 小さな盤の厳密解析（評価関数なし） | **支持** |
| H2 | 読み合いエンジンの評価関数が王手を過大評価している | 読み方の違う Bot で比較 | **反証**（読みの深さ・癖読みに関係なく 96〜97%） |
| H3 | 受ける側が罠の確率を読み違えている（過小評価） | 王手局面で「受ける側の予想」「罠側が実際に置いた確率」「命中率」を比較 | **反証**（予想 34.2% ≥ 実際 27.9% ≒ 命中 27.3%） |
| H4 | 分類が粗く、実は詰みを数えているだけ | 受けの数で分類し直した | **一部支持**: 963 局のうち約 3 割は受けが 1 つの「罠詰み」で、実質の詰み。本当のルーレット（受け 2 つ以上）は約 7 割 |
| H5 | ルーレットが互角の勝負をくじ引きで決めている | ルーレット死の直前の、負けた側の評価 | **反証**（平均 -0.81。互角から死んだのは 7%）。ただし「勝っている側が詰みを読まなくても勝てる」ため、対局は短くなる |

### H1: 小さな盤の厳密解析

`data/exact-3x4.json`, `data/exact-4x4.json`

- **盤と駒**: 3×4 盤（44,900 局面）と 4×4 盤（171,104 局面）。各陣営が玉 + 金 1 枚で、取った金は打てる。
- **解き方**: 全局面について、各手番を「罠側 vs 指す側」の同時手番ゲームとして Shapley の価値反復で厳密に解いた。指す側の利得は「選んだ着地点に罠があるか」だけで決まるので、各手番の均衡は閉じた式で解ける。
- **対局**: 初期局面から均衡戦略どうしで 20,000 局ずつ指させた。

| 4×4 盤 | 罠なし | A | B | C | D |
| --- | --- | --- | --- | --- | --- |
| 決着した割合 | 0% | 99.9% | 2.1% | 85.2% | 0% |
| 決着局のうち ルーレット | — | 22% | 0% | 0% | — |
| 決着局のうち 罠詰み | — | 70% | 58% | 93% | — |
| 決着局のうち 詰み | — | 5% | 24% | 0.3% | — |
| 手数の中央値 | 200（打ち切り） | 8 | 200 | 9 | 200 |

3×4 盤もほぼ同じ傾向（A: 決着 98%、そのうちルーレット + 罠詰み 88%）。

- 罠がなければ、この盤は王手の千日手で引き分け。現行ルールでは、ほぼ必ず「王手の受けを罠で潰す」ことで決着する。罠は、引き分けを勝ちに変える装置として働いている。
- B と D では、王手の応手が罠から守られるので引き分けに戻る（この小さな盤には、罠なしで詰ませる戦力がない）。
- C では「受けが 1 つの王手」だけが致命的になり、決着はほぼ全て罠詰み。

**近似（本物のルールとの違い）**:

1. 罠を置くのは「自分の手が通った後」としている。本物は自分の手より先に置くが、読み合いエンジンの探索と同じ抽象化。
2. 同じマスへの連続設置の禁止は省略した。
3. 割引率 γ = 0.99 を入れ、終わらない対局を引き分けにしている。

- Normal は王手 20 回に 1 回しか罠を当てられない。`bot.ts` の罠の置き方は「相手が駒を取る手・成る手・中央・自玉の近く」の着地点を高く採点する方式で、王手された側の受けを狙う仕組みがないため、と考えている（この理由づけは推測で、未検証）。そのため決着が遅れ、受け損ねや詰みが増える。

### 結論

963/1000 は主に**ルールの性質**（H1）。Bot が影響しているのは、ルーレットと罠詰みの比率と、対局の長さだけ。

このルールでは、王手は「受けの数に応じた確率で即死する推理勝負」になる。そのため、有利な側は詰みを読むより王手を連打する方が速く勝てる。これは A の短さ（中央値 26 手）と、決着の均一さ（王を取る駒の多様性が最も低い）の原因でもある。

## 7. 未検証のこと

- **人間の試遊は一切していない。** 「面白い」の判断は、ここにある数字からはできない。
- B・D の長さには Bot の弱さが混ざっている可能性がある。B・D では勝つのに本当の詰みが必要になるが、2 手読みのエンジンは詰みを探すのが苦手で、「必至（投了相当）」での決着が 17〜50% ある。人間同士ならもっと短いかもしれない。
- 形勢の入れ替わり・逆転の数字は、エンジン自身の評価に頼っている。変種ごとに評価の物差しがずれている可能性がある。
- 厳密解析は玉と金だけの小さな盤。大駒・成り・打ち歩などのある本物の盤で、同じ均衡になる保証はない。罠を置くタイミングと連続設置の禁止も近似している。
- D の「消えた罠の位置は公開しない」は、ほかの選択肢（公開する／次の手番まで持ち越す）と比べていない。
- Strict は各 200 局。95% 区間はおよそ ±7%。
- B・C・D の Bot の思考時間はアプリで測っていない（自動対戦では 1 手あたり数十〜百ミリ秒程度）。

## 8. 今後の研究候補

1. **A と D の試遊**（人間同士・人間対 Bot）。質問案: 負けたとき「読み負けた」と感じたか「運」と感じたか／終盤に何をしていたか。
2. **A を残したまま王手ルーレットを和らげる弱い案**: 「王手された側は罠の候補が 2 マスに絞られる」「王手をかけた側は次の手番に罠を置けない」など。今回の基盤で比較できる。
3. **D の派生**: 消えた罠の位置を公開する／王手で罠が消えるのは「王手をかけた駒の着地点に罠を置いた時」だけにする。
4. **詰み探索の強化**: B・D の長さが Bot の弱さなのかルールなのかを分けるため、王手だけを深く読む延長探索を入れて再計測する。
5. **厳密解析の拡張**: 連続設置の禁止を状態に入れる。盤を 5×5（銀・歩入り）に広げる。
6. **Normal の作り直し**: 今の Normal は罠の置き方が均衡から大きく外れているので、難易度を均衡からのずらし幅で作ると、階段が滑らかになる可能性がある。
